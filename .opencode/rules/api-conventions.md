# API

> Общие правила публичного HTTP API

- Использовать Litestar только как HTTP/ASGI boundary: handler вызывает application use case и не содержит domain rules или persistence orchestration.
- Использовать `msgspec.Struct` для transport DTO/serialization и, по ADR-0004, для domain entities/value objects.
- Не объединять domain и transport Struct: HTTP DTO не передавать в domain model, domain entity не возвращать из handler без явного mapping.
- Проектировать API от утверждённого контракта, а не от внутреннего устройства кода.
- Использовать единообразные ресурсы, HTTP-методы, статусы, пагинацию, фильтры и сортировку.
- Валидировать входные данные на границе доверия до вызова бизнес-логики.
- Не раскрывать внутренние идентификаторы, трассировки, SQL и детали инфраструктуры без контракта.
- Определять идемпотентность и конкурентное поведение для изменяющих операций.
- Изменение публичного API требует обновления контракта, примеров, changelog и contract-проверки.
- Breaking change требует явного подтверждения и плана миграции.
