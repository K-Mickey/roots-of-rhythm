# PostgreSQL session concurrency

> Безопасное использование PostgreSQL session при конкурентной работе

- Не использовать одну session/connection одновременно в нескольких async-задачах или потоках.
- Создавать отдельную session на независимую единицу конкурентной работы.
- Не передавать ORM-объекты между session без явного преобразования или повторной загрузки.
- Не запускать параллельные запросы через одну session.
- Явно определять lifecycle session и гарантировать закрытие при успехе и ошибке.
