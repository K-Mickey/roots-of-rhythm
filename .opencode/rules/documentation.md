# Documentation and SDD

> Spec-Driven Development и обязательная синхронизация документации

- Считать утверждённую спецификацию источником ожидаемого поведения.
- Перед нетривиальной реализацией определить FR, NFR, acceptance criteria, границы и ошибки.
- Обновлять API-контракт до или вместе с реализацией.
- Создавать ADR для решения, которое дорого менять или которое влияет на несколько модулей.
- Документировать публичное поведение и решения, не пересказывать строки кода.
- Не изменять требования задним числом для оправдания реализации.
- Отмечать неизвестное как `TBD` с владельцем решения; не заполнять догадкой.
- После изменения документации проверять ссылки, навигацию и contract-lint, когда они настроены.
