# Authorization

> Проверка доступа по permissions, а не по именам ролей

- Запрещать доступ по умолчанию.
- Проверять permission/capability, а не строковое имя роли.
- Считать роли способом назначения permissions, но не API авторизации бизнес-кода.
- Выполнять проверки на сервере до чтения или изменения защищённых данных.
- Для объектного доступа учитывать владельца, организацию, tenant и другую утверждённую область.
- Не доверять permissions, owner ID и scope, переданным клиентом.
- Изменения модели доступа требуют security-review и тестов после подтверждения.
