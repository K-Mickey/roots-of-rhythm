# Create API MR

1. Проверить Git-корень, рабочее дерево и принадлежность всех изменений текущей задаче.
2. Проверить синхронность спецификации, контракта, примеров, каталога и changelog.
3. Запустить contract-lint и breaking-change diff.
4. Подготовить заголовок и описание: цель, изменения, совместимость, миграция, проверки.
5. Показать пользователю diff summary, результаты проверок и план Git-действий.
6. Без явного подтверждения не создавать ветку, commit, push или MR.
7. После подтверждения выполнить только согласованные действия и вернуть ссылку или идентификатор.
