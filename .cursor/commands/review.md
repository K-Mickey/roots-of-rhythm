# /review

Провести read-only review текущего изменения.

1. Прочитать спецификацию и diff.
2. Искать correctness, security, data loss, concurrency, contract и regression проблемы.
3. Проверить соответствие архитектурным границам и отсутствие ненужной сложности.
4. Для каждого замечания указать файл, точное место, сценарий отказа и приоритет.
5. Не вносить исправления без отдельной команды.
6. Если actionable-проблем нет, сказать это явно и назвать остаточные риски.
