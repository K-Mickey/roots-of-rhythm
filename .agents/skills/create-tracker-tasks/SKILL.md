# Create tracker tasks

1. Прочитать `docs/roadmap/delivery-workflow.md`, утверждённые story и декомпозицию.
2. Для каждой задачи подготовить заголовок, контекст, scope, acceptance criteria, зависимости и проверки.
3. Сохранять ссылки на идентификаторы требований.
4. Не дублировать задачи и не добавлять неутверждённый scope.
5. Read-only проверить существующие issues по requirement/task IDs и source links; не сопоставлять только по заголовку.
6. Показать dry run: `create`, `update`, `no-op`, `conflict`, Project/Milestone mapping и предполагаемый local write-back.
7. Без явного подтверждения показанного batch не выполнять записи во внешнем tracker.
8. После подтверждения создать или обновить задачи через авторизованный коннектор, проверить отсутствие дублей и вернуть identifiers/URLs.
9. Записать tracker links рядом с декомпозицией только после успешного создания, не меняя требования.

Не закрывать, не удалять, не архивировать и не перемещать существующие tracker items без отдельной явной команды. При конфликте ручных изменений остановить конкретный item и запросить решение.
